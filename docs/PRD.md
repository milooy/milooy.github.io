## 배경과 목표

Gatsby 스타터로 만든 블로그를 버리고, 템플릿과 빌드 스크립트를 직접 소유하는 개인 사이트로 다시 만든다. 기준은 하나다. 누가 봐도 진유림이 만든 사이트일 것.

- **왜 지금**: Gatsby는 사실상 메인테넌스 모드다. 사이트 곳곳에 스타터 잔재가 남아 있고, RSS 링크는 스타터 도메인을 가리키고 있다.
- **왜 프레임워크 없이**: AI와 함께라면 몇백 줄짜리 빌드 스크립트는 직접 유지할 수 있다. 사이트 수명을 특정 SSG의 수명에 묶지 않는다.
- **무엇을 피하나**: 누군가를 따라 한 사이트, AI가 찍어낸 듯한 사이트(AI slop).

### 성공 기준

- 개발·리더십 글을 읽는 개발자가 방해받지 않고 끝까지 읽는다.
- 처음 온 사람이 홈에서 바로 '개발하고, 팀을 이끌고, 그림 그리고 노래하고, 책 읽는 사람'이라는 걸 안다.
- 새 글은 MD 파일 하나를 추가하고 push하면 끝난다. HTML은 손대지 않는다.
- 사이트의 장식 요소는 전부 직접 그리거나 만든 것이다. 스톡 일러스트, AI 생성 이미지, 이모지 아이콘은 없다.

## 정체성과 독자

네 가지 자아를 한 사이트에 버무리되, 독자의 90%는 개발자다. 그래서 사이트는 두 겹으로 나눠 설계한다. 글 읽는 곳은 조용하게, 나머지는 나답게.

| 자아   | 드러나는 섹션                         | 독자가 가져가는 것                          |
| ------ | ------------------------------------- | ------------------------------------------- |
| 개발자 | Blog(개발), Toys                      | 실무에서 배운 것, 직접 만들어 돌아가는 것들 |
| 리더   | Blog(리더십), Resume                  | 팀과 제품을 키운 경험과 관점                |
| 예술인 | Drawings, Songs, 사이트 전체의 손그림 | 이 사람만의 손맛                            |
| 독서가 | Books, 책 리뷰 글                     | 무엇을 읽고 어떻게 평가하는지               |

- **주 독자**: 검색이나 공유 링크로 글 한 편에 바로 들어오는 개발자. 홈을 거치지 않는 경우가 많다.
- **두 번째 독자**: 채용 담당자와 동료. Resume와 홈을 본다.
- **그래서**: 글 페이지 자체가 사이트의 첫인상이다. 다른 자아로 가는 길은 글 하단과 상단 내비게이션에 조용히 둔다.

## 디자인 원칙

모든 페이지는 '읽기 모드' 아니면 '전시 모드' 중 하나다. 개성은 전시 모드에서 마음껏 드러내고, 읽기 모드에서는 글 말고는 아무것도 보이지 않는다.

|        | 읽기 모드                                      | 전시 모드                                    |
| ------ | ---------------------------------------------- | -------------------------------------------- |
| 페이지 | Blog 글, Notes, Resume                         | Home, Books, Drawings, Songs, Toys           |
| 장식   | 상단의 작은 손글씨 로고 하나                   | 섹션마다 직접 그린 일러스트와 실물 은유 하나 |
| 움직임 | 없음                                           | hover·클릭에 반응하는 것만. 스크롤 연출 없음 |
| JS     | 0KB 목표                                       | 페이지별 작은 스크립트 하나                  |
| 타이포 | 본문 폭 65~70자, 한글 본문용 폰트, 줄간격 넓게 | 제목에만 개성 있는 서체 허용                 |

### 원칙

1. **손그림이 시그니처다.** 로고, 섹션 일러스트, 구분선, 빈 화면, 404까지 직접 그린다. 스캔한 펜 그림이든 디지털 드로잉이든 손으로 그린 것이어야 한다.
2. **읽기 모드는 도구다.** 코드 블록, 표, 긴 글의 목차가 잘 보이는 것이 예쁘다는 것보다 우선한다.
3. **전시 모드는 섹션마다 실물 은유 하나.** 책장은 책장처럼, 그림은 스케치북처럼. 은유를 겹치거나 섞지 않는다.
4. **다크 모드와 접근성은 기본이다.** 대비 WCAG AA, 키보드로 모든 인터랙션 가능, `prefers-reduced-motion` 존중.

### 하지 않을 것 (anti-slop)

- 보라·파랑 그라데이션, 글래스모피즘, 카드마다 그림자
- 이모지 섹션 아이콘, "Hi, I'm …" 인사말 히어로
- 스톡 일러스트, AI 생성 이미지, 아이콘 팩 기본값 그대로 쓰기
- 스크롤할 때마다 떠오르는 요소, 의미 없는 패럴랙스
- 레퍼런스 사이트(kevintngo.com)의 에셋, 레이아웃, 재질 조합 그대로 가져오기. 가져올 것은 '손으로 만든 것을 장식으로 쓴다'는 태도뿐이다.

## 사이트 구조와 섹션별 요구사항

홈 아래 섹션은 7개다. 상단 내비게이션은 Blog를 맨 앞에 두고, 각 섹션은 읽기 모드나 전시 모드 중 하나를 따른다.

```text
Home  /                       손그림 일러스트, 최근 글
├─ 읽기 모드 (독자의 90%가 머무는 곳 · 장식과 움직임 없음)
│  ├─ Blog      /blog/        개발·리더십 글, 태그로 필터
│  ├─ Notes     /notes/       조각글 타임라인
│  └─ Resume    /resume/      이력서, 인쇄용 스타일
└─ 전시 모드 (직접 그린 손그림 · 섹션마다 실물 은유 하나)
   ├─ Books     /books/       5점 만점, 별점별 책장
   ├─ Drawings  /drawings/    그린 그림 갤러리
   ├─ Songs     /songs/       부른 노래 플레이리스트, SoundCloud로 재생
   └─ Toys      /toys/        직접 만든 것들, 바로 눌러보기
```

독자 대부분은 Blog 글로 바로 들어오므로, 읽기 모드가 사이트의 첫인상이다.

### Home · `/`

- 첫 화면은 이름, 한 줄 소개, 직접 그린 일러스트 한 장. 네 자아가 그림 안에 들어 있어 누르면 해당 섹션으로 간다.
- 그 아래 최근 글 5개, 최근 조각글 3개, 섹션 바로가기.
- 움직임은 첫 방문 때 짧게 한 번만.

### Blog · `/blog/`, `/blog/<slug>/` (읽기 모드)

- 목록: 연도별로 묶고, 한 줄에 날짜 · 제목 · 한 줄 설명 · 태그. 썸네일 없음.
- 카테고리 대신 태그를 쓴다. 목록 위의 태그를 누르면 그 태그 글만 보이고, 태그마다 고유 URL(`/blog/tags/<tag>/`)을 갖는다.
- 본문: 제목, 날짜, 태그, 읽는 시간, 긴 글은 목차, 코드 하이라이팅, 이전·다음 글, giscus 댓글.
- RSS는 기존 주소 `/rss.xml`을 유지한다.

### Notes (조각글) · `/notes/` (읽기 모드)

- 세로 타임라인, 최신이 위. 한 조각 = 날짜·시간 + 짧은 글, 사진 한 장이나 링크 하나는 선택.
- 개별 페이지 대신 앵커 링크(`/notes/#2026-10-26-1430`)로 공유한다.
- 연도·월 단위로 끊어 보여주고, 많아지면 연도별 페이지로 나눈다.

### Books · `/books/` (전시 모드)

- 5점 만점 별점별 선반. 위에서부터 5점, 4점대, 3점대, 2점대, 1점대 이하.
- 책 한 권 = 책등. 책등에는 제목과 저자, 색은 표지에서 뽑는다.
- 책등을 누르거나 hover하면 책이 빠져나오며 표지, 별점, 한 줄 평, 읽은 해를 보여준다. 리뷰 글이 있으면 링크한다.
- 읽은 연도로 필터할 수 있다. 정렬은 별점으로 고정.

### Drawings · `/drawings/` (전시 모드)

- 그림이 주인공인 갤러리. 스케치북을 펼친 듯한 배치에 그림마다 제목, 날짜, 재료.
- 누르면 크게 보기, 키보드 ← →로 넘기기.
- 아래에 B컷 휴지통. 걸기엔 민망한 그림을 구겨진 종이처럼 담아 두고, 열면 휴지통이 엎어진다. 종이에 마우스를 올리면 펴지면서 색이 돌아온다. B컷은 md 없이 `content/drawings/b-cuts/`에 그림 파일만 둔다.
- 원본은 보존하고, 웹용 크기는 빌드에서 만든다.

### Songs · `/songs/` (전시 모드)

- 플레이리스트 형태. 위에 직접 그린 커버 한 장, 아래에 번호 · 곡명 · 원곡자 · 녹음 날짜로 된 트랙 목록.
- 트랙을 누르면 페이지 안의 SoundCloud 위젯 하나가 그 곡을 틀어준다. 트랙마다 짧은 코멘트를 펼쳐 볼 수 있다.
- 애플 뮤직에서는 플레이리스트 구조(커버 + 트랙 목록)만 빌린다. 블러 배경 같은 시각 스타일은 따라 하지 않고, 개성은 직접 그린 커버로 낸다.
- 계정: [soundcloud.com/hellojayjin](https://soundcloud.com/hellojayjin)

### Toys · `/toys/` (전시 모드)

- 직접 만든 것들을 '가지고 놀아볼 수 있게' 보여준다. 스크린샷보다 움직이는 미리보기나 바로 눌러볼 수 있는 데모.
- 토이마다 이름, 한 줄 설명, 만든 해, 쓴 기술, 데모·소스 링크, 만든 이야기.
- 재미있는 인터랙션을 쓰더라도 전체 목록은 항상 한 번에 보인다.
- 처음에는 TBD 더미 하나로 화면만 만들고, 실제 토이는 나중에 채운다.
- GitHub에서 찾은 후보: recall, easybusy, donedrop, todoy, cat-jjal-maker, 청첩장(yurim-josh-wedding-card), remote-or-flexible-work-company-in-korea, TIL, Boxiting, j-world(주소창월드), raycast-extensions.

### Resume · `/resume/` (읽기 모드)

- 한 장짜리 문서. 경력은 회사별로 접고 펼칠 수 있고, 발표와 활동은 목록으로.
- 인쇄용 스타일을 따로 두어 브라우저에서 바로 PDF로 저장할 수 있다.
- 기존 MDX 내용(토스, Zepl 등)을 옮긴다.

## 콘텐츠 모델

모든 콘텐츠는 MD 파일 하나와 frontmatter다. 책 한 권, 그림 한 장, 노래 한 곡도 파일 하나이고, 빌드가 섹션 템플릿에 맞춰 HTML을 만든다.

```text
content/
  posts/      <slug>.md              블로그 글
  notes/      <YYYY-MM-DD-HHmm>.md   조각글
  books/      <slug>.md              책 한 권
  drawings/   <slug>.md + 이미지     그림 한 장
  songs/      <slug>.md              노래 한 곡
  toys/       <slug>.md + 미리보기   토이 하나
  pages/      <slug>.md              단독 페이지 (방명록 등)
  resume.md
templates/    레이아웃과 섹션별 템플릿 (.ts)
assets/       손그림, CSS, 페이지별 JS
static/       그대로 복사되는 파일 (favicon, 발표 자료 등)
build.ts
```

| 타입    | 필수 필드                                                       | 선택 필드                                                  | 본문           |
| ------- | --------------------------------------------------------------- | ---------------------------------------------------------- | -------------- |
| post    | `title`, `date`, `tags`                                         | `description`, `updated`, `draft`                          | 글             |
| note    | `date`(시간 포함)                                               | `title`, `image`, `link`                                   | 짧은 글        |
| book    | `title`, `rating`(0.5~5, 0.5 단위), `readAt`(YYYY 또는 YYYY-MM) | `author`, `cover`, `spineColor`, `isbn`, `review`(글 slug) | 한 줄 평, 메모 |
| drawing | `title`, `date`, `image`                                        | `medium`(재료)                                             | 그림 이야기    |
| song    | `title`, `date`, `soundcloud`(URL)                              | `original`(원곡자, 없으면 자작곡), `duration`, `cover`     | 코멘트         |
| toy     | `title`, `year`, `summary`, `url`                               | `repo`, `stack`, `preview`                                 | 만든 이야기    |
| resume  | `title`                                                         |                                                            | 경력 본문      |

- 빌드는 frontmatter를 검사해서, 필수 필드가 없거나 형식이 틀리면 파일 이름과 필드를 찍고 실패한다.
- `draft: true`인 글은 개발 서버에서만 보이고 배포에서는 빠진다.
- 본문에는 HTML을 그대로 쓸 수 있다. Resume의 접는 경력은 `<details>`로 쓴다.
- 책의 `author`는 기존 결산 글에 없는 경우가 많아 선택 필드로 둔다.

## 빌드와 배포

SSG 프레임워크 없이 `build.ts` 하나가 `content/`와 `templates/`를 읽어 `dist/`에 HTML을 쓴다. 의존성은 5개 이하로 유지한다.

### 스택

- **런타임**: Node 24 LTS. TS 파일을 별도 컴파일 없이 바로 실행한다.
- **의존성**: 마크다운 파서, YAML 파서, 코드 하이라이터(Shiki, 빌드 타임), 이미지 리사이즈(sharp, 필요해지면).
- **템플릿**: HTML 문자열을 돌려주는 TS 함수. React나 JSX 런타임은 없다.
- **CSS**: 공통 파일 하나 + 섹션별 파일. 색과 간격은 CSS 변수로 두고 다크 모드를 같이 정의한다.
- **클라이언트 JS**: 전시 모드 페이지에만, 페이지별 vanilla 모듈 하나.

### 빌드가 만드는 것

1. 글 페이지와 섹션 목록 페이지. URL은 `dist/<path>/index.html` 형태로 끝에 `/`가 붙는다.
2. `/rss.xml`, `/sitemap.xml`, `404.html`.
3. 웹용 이미지(그림, 책 표지, 토이 미리보기).
4. 옛 주소마다 새 주소로 보내는 리다이렉트 HTML.

### 개발과 배포

- `npm run dev`: 파일이 바뀌면 다시 빌드하고 브라우저를 자동으로 새로고침한다. 서버는 `node:http`로 직접 만든다.
  - `assets/css`만 바뀌면 빌드하지 않고 그 스타일시트만 갈아 끼운다. 화면 상태(스크롤, 열린 창, 재생 중인 노래)가 그대로 남는다.
  - 빌드가 실패하면 에러를 브라우저 화면 위에 띄운다. 고쳐서 빌드되면 사라진다.
- `npm run build`: 배포용 빌드. 글 100개 기준 수 초 안에 끝나야 한다.
- main에 push하면 GitHub Actions가 빌드해서 GitHub Pages에 올린다. 기존 `gatsby.yml`을 대체한다.
- 도메인은 `milooy.github.io`를 유지한다.
- 분석은 지금 GA4 측정 ID를 그대로 쓰고, 플러그인 없이 최신 gtag 스니펫을 직접 넣는다. 댓글은 giscus.

### 주소 유지

- 지금 주소는 폴더 기준이다(`/dev/230402-type-guard/`). 새 주소는 `/blog/230402-type-guard/`처럼 파일 이름을 slug로 쓴다.
- GitHub Pages에는 서버 리다이렉트가 없다. 옛 주소마다 canonical과 meta refresh를 넣은 HTML을 빌드가 만든다.
- `/category/<x>/`는 `/blog/tags/<x>/`로 보내고, `/rss.xml`은 그대로 둔다.
